# AGENTS.md

## Structure

- **Regra do contexto**: sempre que a janela de contexto estiver ficando cheia (risco real de esquecer detalhes importantes deste trabalho), o assistente DEVE me avisar explicitamente e me dizer exatamente o que eu devo falar para ele retomar de onde parou — ou seja, listar os arquivos em andamento, o que falta fazer, comandos de verificação e pontos sensíveis (ex.: não commitar, nomes de endpoints, segredos em uso). Isso é uma regra: avisar é obrigatório, não opcional.
- **Débitos técnicos**: todo item que ficar **decidido para implementar no futuro** (decisão tomada na conversa, mas ainda não feita) deve ser registrado em `debitos_tecnicos.md` (raiz do repo) com status/quem resolve/passo a passo/links/verificação. Ao concluir, marcar `✅` (ou remover) e refletir no `PLAN.md`. O arquivo também pode acumular pendências de infra que dependem do dono (ex.: contas externas). Ler antes de começar qualquer fase nova e atualizar ao final.
- Two independent apps, **no root `package.json` / workspaces**. Run commands inside `front/` or `back/`; never `npm install` at the repo root.
- `front/` = Angular 20 (standalone), deployed to Vercel.
- `back/` = NestJS 12 (Node ESM) with REST + WebSocket (Socket.io), deployed to Render.
- **No Supabase.** Postgres is **Neon** (serverless) accessed via **Prisma**; auth via **Neon Auth** (Managed Better Auth, beta — users/sessions live in the `neon_auth` schema of the same DB); images go to Cloudflare **R2**; the **password-recovery email is sent by Neon Auth itself** (SMTP/remetente configurado no console da Neon — nosso back não envia e-mail); storage and realtime are implemented in the API itself (no RLS on business tables — the API is the only data access layer).
- **DB schema is applied** (M1): `prisma/migrations/20260910114719_m1_core` — see `PLAN.md`.
- Docs/prose (PLAN.md, README) are pt-BR; keep new prose in pt-BR. Code in English.

## Setup gotchas

- Local Node is **22.16.0**. `@angular/cli` is deliberately pinned to **v20** because CLI 22 requires Node >= 22.22.3. Do not upgrade Angular or run `ng update` unless Node is bumped first.
- `back/.npmrc` sets `legacy-peer-deps=true`. **Required**: plain `npm install` crashes on npm 10.9.2 resolving vitest peer deps (`Cannot read properties of null (reading 'edgesOut')`). Never remove this file.
- Back reads env from `back/.env` (copy from `.env.example`): `DATABASE_URL` (Neon DSN, `sslmode=require`), `PORT`, `NEON_AUTH_ISSUER` (issuer/audience do JWT — host `<projeto>.neonauth.sa-east-1.aws.neon.tech`, sem o sufixo `/neondb/auth`), `APP_JWT_SECRET`, `FRONT_URL` (origin pra Neon Auth) e `ADMIN_SISTEMA_EMAIL` (opcional — promove o admin raiz no boot). Neon project not created yet, so `GET /health` returns `degraded` until `.env` is filled.
- Front env lives in `front/src/environments/environment.ts` (`apiUrl`) — points to localhost:3000 in dev.
- Prisma: after changing `back/prisma/schema.prisma`, run `npx prisma migrate dev` (creates/applies migration) — it also regenerates the client. For one-off DB tweaks without a migration, use `npx prisma db push`. Never hand-edit generated client.

## `back/` — NestJS 12

- ESM (`"type": "module"`): relative imports **must** include the `.js` extension (`./app.controller.js`, `../prisma/prisma.service.js`). New files must follow, or build fails.
- Linter is **oxlint**, not eslint: `npm run lint`. Formatter: `npm run format` (prettier).
- Tests via vitest: `npm test` = unit (`**/*.spec.ts`); `npm run test:e2e` = e2e (`**/*.e2e-spec.ts`, separate `vitest.config.e2e.ts`).
- Dev server: `npm run start:dev` (port 3000, reads `PORT`). Build: `npm run build` (nest build).
- Database: `PrismaService` in `src/prisma/` is a `@Global` module — inject it anywhere. `GET /health` runs `SELECT 1` via Prisma. CORS is enabled in `src/main.ts`.
- Auth is **Neon Auth** (Managed Better Auth). **No navegador o SDK NÃO consegue o JWT da Neon**: o `/get-session` manda o JWT EdDSA só no header `set-auth-jwt`, e como a Neon não envia `Access-Control-Expose-Headers` pra esse header, o browser o esconde (SDK `adapter-core-*.mjs` faz `ctx.response.headers.get("set-auth-jwt")` → `null`). O `data.session.token` retornado é o token **opaco** (o cookie é `HttpOnly`, valor `bare.mac`; `neon_auth.session.token` guarda a versão `bare`). Por isso o front chama `POST /auth/exchange` com o token opaco → o back resolve em `neon_auth.session` (`token = <opaco>` ou `LIKE '<opaco>.%'`, `expiresAt > NOW()`, ban ~ `neon_auth."user".banned`) e emite um **JWT HS256 próprio** (`APP_JWT_SECRET`, iss/aud `cardapio-online`, exp 6h) que passa a ser o Bearer. `AuthService.validateSession` tenta o JWT da aplicação primeiro e cai no caminho legado da Neon (verifica assinatura com as chaves de `neon_auth.jwks` — `kid` uuid → cast `${kid}::uuid`; publicKey é JSON `{kty OKP, crv Ed25519, x}`; `jwtVerify` com `algorithms: ['EdDSA']` explícito) + `exp`/`iss`/`aud` (= `NEON_AUTH_ISSUER`) + `banned: true` + sessão viva por `userId` (cast `${id}::uuid`). Prisma `$queryRaw` não faz cast implícito de text → uuid — sempre cast. Front: `auth.service.ts` troca o opaco por JWT quando `ehJwt()` falha (token sem 3 segmentos ou payload sem `sub`+`exp`).
